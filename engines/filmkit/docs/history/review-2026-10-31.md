## HIGH

### H1. Title and steps type is clipped at the bottom, at rest: descenders (g y p q j), commas and CJK bottoms are cut off.  REPRODUCED
- `filmkit/elements.py:124` (0.1.3: `:138`) title, `:332` (0.1.3: `:369`) steps. The line is drawn into a scratch image of height `int(size * lead * q) + 12` with the text top at 6 px; `paste_clipped` pastes it.
  A face whose ascent+descent is more than about 1.12 em loses its bottom. Noto Sans CJK (the face the docs name) has ascent 1.16 em, descent 0.29 em; Pillow's default face is the same.
- Run: DEMO, then spec with one title `{"element":"title","t0":0,"t1":6,"lines":["gypsy jqp","你好，世界"],"x":64,"y":400,"size":124,"font":"black"}`,
  `fonts` = the four `~/Library/Fonts/NotoSansCJKsc-*.otf`, `FILMKIT_NO_SYSTEM_FONTS=` (empty), `python3 -m filmkit still film.json --at 3 --out s.png`.
  Image: `$S/clip_title_compare.png` (left: filmkit, reads "gvpsv iap"; right: the same text drawn by Pillow unclipped).
- Measured (`$S/t6_clip.py`, Noto Sans CJK Black): lost at rest = 12 px at size 60, 30 px at size 124 for "gypsy jqp"; CJK "你好，世界" loses 7 px / 20 px; all-caps Latin loses 0 (which is why the demo and tests look right).
  The default face loses 13 / 20 / 30 px at 60 / 124 / 200. A preview (q 0.25) clips about half as much in full-size terms (by calculation: the fixed +12 px slack does not scale), so the preview does not show the real damage either.
- Should: the whole glyph at rest. The clip is meant as the reveal mask while the line rises, so keep the mask but size it from the font.
- Fix: in both places build the scratch from the font metrics:
  ```python
  f = cx.font(p["font"], size); asc, desc = f.getmetrics()
  tmp = Image.new("RGBA", (cx.W, asc + desc + 12), (0, 0, 0, 0))      # was int(size*lead*cx.q)+12
  ```
  (steps: the same with `cx.font("black", size)`), and keep `paste_clipped(layer, tmp, int((ly - 6) * cx.q))`.

### H2. The delivered H.264 is encoded with the BT.601 matrix and carries no colour tags; players that assume BT.709 for HD show shifted colour.  REPRODUCED
- `render.py:129-130` (footage: RGB rawvideo to `-pix_fmt yuv420p`, no matrix, no tags), `:131-132` (ProRes overlay, same), `:156-160` (final encode, no tags). ffmpeg's default RGB to YUV is BT.601; nothing says so.
- Run (`$S/t12_color.py`, `$S/t13_colorcmp.py`): a 1 s film of one image with pure R/G/B/Y/C/M, two skin tones, grey, white, black; `grade.look = natural`, `crf 18`, full 1080x1920.
  `ffprobe`: `color_space=unknown color_range=unknown`. Decoding the file as BT.709 (what browsers, phones and mpv do for untagged HD):
  green (0,255,0) -> (0,215,0); red (255,0,0) -> (255,23,0); magenta -> (255,38,255); cyan -> (0,229,255); (30,120,200) -> (19,115,204); skin (200,150,120) -> (203,152,116). Worst channel error 40 levels.
  Decoding as 601 round-trips (252,0,0 etc.), which is why `still` (RGB PNG) and ffmpeg-based checks look fine.
- Should: what `still` shows is what plays. A film whose product is a colour grade must not shift colour on most players.
- Fix (tested: the pipeline below decodes as 709 to (253,0,0), (0,254,0), (0,0,253)): footage stage `-vf "<lut chain>,scale=out_color_matrix=bt709:out_range=tv,format=yuv420p"`
  plus `-colorspace bt709 -color_primaries bt709 -color_trc bt709 -color_range tv` on the encode; overlay stage `-vf scale=out_color_matrix=bt709:out_range=tv,format=yuva444p10le`; the same four tags on the final output
  (`render.py:159` `tail`). Add `color_space` to `inspect` so a test can assert it.

### H4. Shots that come out black, or wrong, with `validate` ok, `render` exit 0 and no warning.  REPRODUCED
`media.py:60-67` starts the decoder with `stderr=subprocess.DEVNULL` and never looks at its exit code; `media.py:75-82` turns "no frame" into a black frame. So any decode problem is a black shot. Frame at t=1.0 of the render of DEMO with one edit (`$S/sheet1.png`):
- `shots[0].in = 10` (clip is 4 s): black for the whole shot. (`validate`/`check` never compare `in + span*speed` with the clip's length.)
- `assets.a.path = "audio_only.m4a"` (declared `video`): `probe` returns w=h=0 and the shot is black, no crash.
- `assets.a.path = "photo.jpg"` or `logo.png` declared `video`: black (`ffmpeg -ss 0.000 -t 2.7 -i photo.jpg ...` yields 0 bytes; with `-ss 0.5` on a PNG also 0).
- `shots[0].speed = 1e9` or `Infinity` (JSON `1e999`): black (`PTS/inf`). `speed = 1e-9`: the preview took 72 s instead of 6 s.
- `in: -1`: ffmpeg clamps to 0, the clip plays from the start (silently).
- An `image` asset that is really a video (`photo` path = a.mp4) crashes with `UnidentifiedImageError` at the start of render (cheap, but a traceback, see H3).
- Should: a problem line at validate time, or at least an error when a shot decodes no frame.
- Fix: `validate` probes each video asset once (`ffprobe`: has a video stream, `duration`), and for each shot checks `in >= 0` and `in + (end-start+din/2+dout/2)*speed <= duration + 0.1` (warn only if the clip is meant to hold its last frame: say so in the docs); checks `speed` within e.g. [0.05, 20]; checks an `image` asset opens with Pillow and a `video` asset has a video stream.
  In `Shot.source_frame`, when `self.last is None` and the stream is empty raise `FilmkitError(f"no frame decoded from {path} at in={in}")`; keep the decoder's stderr (a pipe read at close) so the message says why.

### M6. A failed ffmpeg child is never noticed; `--workdir` / `TMPDIR` with `: , ' [ ] \` breaks the grade filter.  REPRODUCED (`$S/t16_paths.py`, `$S/t34_grade.py`)
- `render.py:129-149`: `foot` / `over` are `Popen`'d, their exit status is never read. When `foot` dies the next `foot.stdin.write` raises `BrokenPipeError` (a traceback; the real message is only on the child's own stderr). `render.py:146` (`foot.stdin.close()`) can raise too and skip `over.stdin.close()` (READING).
- `grade.py:37`: `lut3d=file={cube}` is put into a filter graph unescaped. `--workdir "w:colon"`, `"w,comma"`, `"it's"`, `"br[ack]et"`, `"back\slash"` all end in `BrokenPipeError`; space, `%`, `=` work. The default workdir is under `$TMPDIR`, so a `TMPDIR` with such a character breaks every render and every `still` (`render.py:182`). `grade.over.grain: 500` the same way.
- Fix: escape the path for the filter (`str(cube).replace("\\","\\\\").replace(":","\\:").replace("'","\\'").replace(",","\\,").replace("[","\\[").replace("]","\\]")`) or, simpler, run the child with `cwd=workdir` and pass the bare `grade.cube`; in the loop `except BrokenPipeError:` -> `foot.wait()` and `raise FilmkitError(...)` with the child's stderr (give them `stderr=PIPE` read at the end, or a log file in the workdir); check `returncode` after each `wait()`.

### M7. Audio: the film's tempo is not used, the voice is not levelled, a silent channel is not noticed.  REPRODUCED (`$S/t9_audio.py`, `t10_duck.py`, `t11_bpm.py`, `t33_lufs.py`)

A voice file about 46 dB below full scale: ducking measured -0.0 dB instead of the spec's `duck_db -7`, and the voice sits 15 dB further under the bed than a loud file; the balance shifts 1:1 with the file's level (docs craft rule 5: "the voice is the loudest thing"). - `audio.py:133` `pan=mono|c0=c0` takes channel 0: a stereo voice file with the voice on the right channel only reads as total silence, `check.timing` and `mix` say nothing (`read_audio` peak 0.0). Warn when a voice line's peak is below -60 dBFS, or when channel 1 is much louder than channel 0.
- `audio.py:56`: a voice (or effect) with `t < 0` is dropped whole (`i >= 0`), silently; validate only requires a number.
- `audio.py:201-202`: a film shorter than about 0.35 s crashes (`np.convolve(..., "same")` returns the longer operand: `operands could not be broadcast together`); 0.36 s runs but `mix_lufs: None` (no 400 ms block), unnormalised, no warning. ## LOW

### L1. Relative spec paths: file names that look like ffmpeg options or URLs fail.  REPRODUCED (`$S/t17_assetnames.py`)
`make_ctx` (`render.py:27-29`) and `audio.mix` (`:185`) pass `base_dir / p`; when the spec is given as a relative path (`filmkit render film.json`, the normal way) `base_dir` is `.` and the argument is the bare name. Asset `my:clip.mp4` -> `ffprobe failed: Protocol not found`; `-lead.mp4` -> `Missing argument for option`; `concat:x.mp4` is parsed as the concat protocol. Absolute spec path: all fine. Spaces, quotes, brackets, commas, `=`, CJK names are fine.
Fix: `base_dir = Path(spec_path).resolve().parent` in `load()`.

### L2. The bitrate floor assumes the audio is 192 kbps.  REPRODUCED (`$S/t14_floor.py`)
`render.py:167` passes `192 if sound else 0`. With a silent soundtrack (`music: {"bed": false}`, no voice) the AAC stream is 2 kbps: `video_kbps` was reported 1619 vs 1799 measured (per-stream packet sums), so a floor could be called unmet, and re-encoded needlessly, or wrongly reported. With sound: reported 1498 vs 1488 measured (container overhead counted as video, 10 kbps). Fix: take the stream's real size from `ffprobe -show_entries packet=stream_index,size` (or `stream=bit_rate` when present) instead of subtracting a constant.

### L3. Fonts.
- `fonts.py:11-17` **READING**: the fallback names are `NotoSansCJKsc-*.otf` (the split OTF release, as installed on this Mac). Debian/Ubuntu `fonts-noto-cjk` installs `NotoSansCJK-Regular.ttc`/`-Bold.ttc` under `/usr/share/fonts/opentype/noto/` (Black and Medium only with `fonts-noto-cjk-extra`), so on a Linux server the fallback finds nothing and CJK renders as Pillow's Latin-only face. A `.ttc` loads index 0 (the Japanese variant) unless `index` is given. Not verified on Linux.
- Missing glyphs print as boxes, `check` says `fonts: []`, `ok: true`. REPRODUCED (`$S/glyph_crop.png`: "健康 💊 ✓ ệ ñ" in Noto Sans CJK Black: the pill emoji is a tofu box). A glyph test (render each distinct character, compare with the `.notdef` mask) would catch it.
- `font: "heavy"` (an unknown role) silently uses Pillow's default face (`fonts.py:50`, even when four real fonts are configured). REPRODUCED. Validate against `ROLES`.

### L4. Footage properties not read.
- Sample aspect ratio is ignored: a 960x1080 clip with SAR 2:1 (displays 16:9) is used as 960x1080 (squeezed). REPRODUCED (`probe` returns w=960 h=1080; the pipe gives 960*1080*3 bytes). Fix: add `scale=iw*sar:ih,setsar=1` to the decode chain (`media.py:66`) and `probe` w from it.
- HDR (HLG/PQ, BT.2020, 10-bit) phone clips go through `-pix_fmt rgb24` with no tone mapping, so they will look flat. **READING**, not rendered (no ground truth here). Warn from `probe` when `color_transfer` is `arib-std-b67` or `smpte2084`.
- `media.py:28-29` `float(num)/float(den or 1)`: `r_frame_rate` `0/0` raises ZeroDivisionError, and the value is not used anywhere. **READING**.

### L5. One-frame slip between `Shot.first` and the render loop.  REPRODUCED by arithmetic (the same expressions), not by a render
`media.py:37` uses `ceil(start*fps - 1e-6)` but `render.py:71` tests `s.start <= t` with no tolerance. When the window start is a hair above a frame time (fps 25, cut 2.08, dur 0.4: window start 1.8800000000000001) the shot's stream frame 0 is shown one frame later than `still` assumes (`n = round(t*fps) - first`), so `still` and render differ by one source frame for that whole shot. 338 of 216,000 realistic cases (3-decimal cuts, 2 to 20 s, dur 0.2 to 0.5) at 24/25/30 fps. Fix: compare with `s.start <= t + 1e-6` in `footage_frame`.

### L6. Temp dir cleanup relies on a finalizer.  REPRODUCED for SIGTERM
`render.py:121-171`: `tmp.cleanup()` is not in a `finally`. Ctrl-C and Python exceptions are fine (the finalizer runs; no `filmkit-*` left, no ffmpeg left: tested), but SIGTERM (a job timeout, `timeout(1)`) leaves `filmkit-xxxx` (about 120 MB per 6 s film: footage CRF 10 plus ProRes 4444 overlay, so about 0.9 GB for 44 s). Fix: `try/finally` around the whole body and a SIGTERM handler that raises `KeyboardInterrupt`.

### L7. Smaller silent behaviours.  Mostly READING, noted where run
- `dim` and `blur` and `camera.center` are ignored for `fit: "card"` shots (`media.py:108-109` returns before `:116-121`). READING.
- A transition without `dur` is a hard cut; unknown `grade.over` keys (`"grane"`) are ignored; `contrast: NaN` renders. REPRODUCED.
- `scrim.bottom_alpha: 300`: `render.py:49` `astype(np.uint8)` of an out-of-range float saturates on arm64 (255, seen) and wraps on x86 (READING). Clamp it.
- `fps: 29.97` is refused ("must be a positive integer"): a limit, say so in the docs (NTSC clients). REPRODUCED.
- `duration` shorter than one frame (0.01 s) passes validate and the last ffmpeg fails with `Stream specifier ':v' in filtergraph description ... matches no streams`. REPRODUCED.
- A shot of one frame, or shorter than a frame, renders (a sub-frame shot is simply never shown). REPRODUCED.

### L8. Text shaping.  READING
`track_text` (`elements.py:39-53`) draws one character at a time: no shaping, so combining marks, ligatures, ZWJ emoji sequences and complex scripts (Thai, Arabic, Devanagari) come out wrong; Pillow here has no raqm so Latin kerning is not lost (measured: per-char sum equals the whole-string width). CJK and precomposed Latin are fine.

### L9. Hardening for untrusted media.  READING plus one probe
Spec assets are handed to ffmpeg with its default demuxers. A text file named `evil.mp4` containing an `ffconcat` script is recognised as the concat demuxer (`ffprobe` reports `format_name=concat`; safe mode limits it to relative names, so no exploit found), an `#EXTM3U` one is refused by extension. Cheap hardening: `-protocol_whitelist file,pipe` and an allow-list of `format_name` from `probe` (mov, matroska, image2...).
