# Lessons

What the source project and the skill packs after it paid for, kept here when the code that carried a lesson is gone or not yet written. Each lesson is at most 150 words: the rule, what it cost, where it was seen and where the detail lives; the long form stays in the skill pack that paid for it. `tests/test_docs_build.py` holds the cap.

## Pulling into raw (from `kit/pull.py`, removed in kit 0.7.0)

`kit/pull.py` merged pulls into raw, planned long pulls in chunks and kept a gap ledger; nothing imported it, so it went ([the 2026-10 restructure](history/restructure-2026-10.md), phase 5; last version `git show 8e13e16:kit/pull.py`). *Paid for:* pulls replaced raw while the platform keeps only months; a late resumed report put old numbers back; an unreadable file was overwritten; a killed long pull started over and the quota ran out; a run cleared the gap list the next run needed. The rules: a pull is merged by natural key, newer wins per key, days outside the window stay, raw never shrinks; an unreadable raw file is moved aside, never overwritten; a long window is chunked with the plan saved after every step; every gap goes into an append-only ledger with its reason. Before writing a pull layer again, compare dlt and Airbyte's Amazon Ads source.

## Open questions that never hold the plan (from `kit/questions.py`, removed in kit 0.42.0)

The module checked a skill pack's open questions and was never imported (it was parked as ROADMAP P1, removed 2026-10-30; last version kit 0.41.0). The rule it checked: **an open question never holds the plan.** Each question names `by_data`, the data that will answer it without asking anyone (a kind from the pack's closed list, or `ask_only`), and `meanwhile`, what the plan does until then, which is an action, never a wait: "write the template and make no video" passes, "TBD" does not. When the data arrives, a read-back lists the questions it can answer with the data's fingerprint, until the answer is recorded; the owner is asked only what no data can answer. *Seen once:* the video-ads skill pack (owner decision, 2026-10-13), whose client rarely knows such answers while the results file it sends back answers some; its insight page groups the questions by who can answer them.

## Paid generation jobs (from adcut-harness, its first real batch, 2026-10-06)

A job that pays per generated asset. *Paid for:* a plan priced a re-run the job then skipped; a paid task's download failed and the resumed job refused it as already paid; QC passed takes with burned-in captions and an invented product; a queued job died when the OS unmounted its external disk, and nobody was told. The rules: a plan prices only what the run will do, a skipped item is 0 and named; a delivered file's identity is never reused; a paid call is resumable by its provider task id, so one call is charged once; check the generated parts, not only the finished product; prefer a free cover to a paid retry; a detached job writes an exit marker, and one with none whose pid is gone is reported once as "stopped without an end". Keep the pack and its data on the internal disk ([install checklist](../templates/install-checklist.md#scheduled-tasks-and-long-jobs)).

## Design and a synthetic demo before code (from adcut-harness X45, 2026-10-13)

A feature an owner must understand and steer starts with research and one page the owner decides on, every ask with a recommended answer, then a clickable demo of the real page drawn by the pack's own renderer from a synthetic world, and code only after the yes. *Paid for:* the owner confirmed four decisions in one reply; writing the page answered each trap the research had found before any was code; the demo held no client data, so it could be shown around. Rules: append-only columns are proven on a scratch copy of real data before the page fixes them; a demo is shared only when synthetic, marked, and a fail-closed client-term scan found nothing; once the code exists the pack draws the demo itself to the same link. Steps and checklist: [design-first.md](../templates/design-first.md). *Seen once* (the video-ads skill pack, ROADMAP X45).

## A guard's refinement never costs the recall it had (from the playbook's ssot write rule, kit 0.26.0, 2026-10-13)

A guard that scans code for a forbidden act (a pack writing into `ssot/`) prefers a false hit, which one allowlist row with its reason answers, to a miss, which nobody sees. *Paid for:* `kit.guards.ssot.check_writes` went through four review rounds in one day; each refinement that removed a false hit missed writes the previous version caught, and 0.26.0 shipped with misses until 0.26.1 compared every case with 0.25.0. Rules: a refinement ships with the cases the old version caught as must-hit cases in the guard's self-test (`_WRITE_CASES`, `writes_self_test()`), and the review compares both versions on them; when a refinement's second review round finds new misses, drop it and add the allowlist row instead; a guard says which way it errs, in its docstring and its changelog line. *Seen once* (this playbook, PRs 88 and 89).

## A past winner the skill pack cannot say is studied for its mechanism, never copied

When a pack reads a client's past results ([path-weights](path-weights.md#past-results-a-gap-signal-never-a-weight)), the strongest ad may win on an angle no template or plan direction states. It is not made a template or a move: the pack learns the mechanism and proposes that, in its own words (whom it reached, how it opened, why people converted), with the ad's id and numbers as evidence, for a person to confirm. A strong ad the plan can say is a template gap; the mechanism is still what is studied. A reference ad the client hands over to copy is the client's request, built faithfully, its risks warnings a person may waive ([claim-scope waivers](../templates/claim-scope.md#waivers)); the pack never promotes a past ad by itself. *Why:* the owner, on the first client's strongest ad: learn the logic, not the case. No code enforces this. *Seen once* (the video-ads skill pack, 2026-10-13, ROADMAP D64).

## An export branch never merges back (from the SEO skill pack, 2026-10-13)

A pack packaged for someone else (a use-case library that ships `git archive` of a branch, no real client name) gets a branch of its own: main merges into it, it never merges into main. Its packaging and its de-identification live only there, and main's README says so; the scan for real names runs on the export branch over what the archive ships, and the name list does not ship. Before a packaging file lands on main, name what in the code, tests or docs reads it: a file nothing reads belongs on the export branch. *Paid for:* the first export branch was merged into main, which then carried files nothing read; merged back later, its placeholders would have replaced the real names main's docs use. *Seen once:* the SEO pack (commits "remove the fde-usecase packaging from main", "de-identify the fde-usecase export").

## Checking the specification and the tests (from the SEO skill pack, 2026-10-15)

Two questions an owner cannot answer by reading: could another agent rebuild this from the spec, and do thousands of assertions guard anything? Both take an hour or two, at a milestone, never in CI. **Rebuild trial:** a fresh agent in a sandbox holding only the spec and a few visible examples re-implements a few pure-function engines; hidden cases come from the real implementation; the product is its `GUESSES.md`, the list of what the spec lacks. A registry-driven engine was rebuilt 83 of 83; rules that lived only in code scored 40 of 47 and 10 of 16. **Mutation sample:** 40 to 50 random one-token mutants, run against the tests that mention the module; 36 of 45 caught, all 8 in the gate and the human tables; the survivors were untested boundaries. *Seen once:* the SEO pack; the full method is in its `docs/playbook-lessons-2026-10.md`.

## Research is kept, not repeated (from the video-ads skill pack, 2026-10-22)

A question looked up (platform documents, papers, vendors) is a file in `docs/research/` with a row in its README: the question, the date, the answer in one line, where it is used; a test fails on a file with no row or a row with no file. Every file dates itself, tags each claim *documented*, *vendor*, *academic*, *ours* or *inference*, and says what it could not read. The index is read before anything is researched; what the research changed lands in the design page, which cites the file and never carries the search. A whole-pack survey is a dated scan in `docs/prior-art/` with a verdict per module and a sources registry ([auditing a pack](../templates/prior-art-scan.md#auditing-a-skill-pack-that-already-exists)); a link the owner pastes is a short lookup ([quick scan](../templates/prior-art-scan.md#a-name-or-a-link-from-the-owner-a-quick-scan)). *Paid for:* rejected options came back on a page the owner was asked to decide. *Seen:* video-ads (`docs/research/`, seven files), Amazon PPC (`docs/prior-art/`, 254 sources).

## The overview shows only what is decided (from the video-ads skill pack, 2026-10-22)

A generated overview ([system-overview.md](../templates/system-overview.md)) can still carry the wrong things: the video-ads one listed algorithms looked at and rejected, a table of options and questions to the owner, because the registries it drew from held the working. The owner's rule: the overview gives the final plan; what is not certain does not go on it; research goes in its own folder. The page draws the decided plan (states, thresholds with whether the owner confirmed each, what is built, what is next), and a registry row is written for the page's reader, never as notes to self. A test fails on a rejected option, a table of alternatives or a question appearing on the page: without it the working came back within a day. A client's own data is drawn only on request and never committed. *Seen once:* video-ads (`tests/test_overview.py`).

## A page made for the owner must open for the owner (from the adcut skill pack, 2026-10-28)

The owner asked for the overview and could not open it, and it kept happening. Two causes: the agent wrote the generated page in a checkout outside the session's folders (the app opens only files inside them), and deleted its copy after sending it, so the link was dead. The rule: **a page or file made for the owner is written in a folder of the session, sent as a file, and never deleted or replaced by a path outside the session.** A generated page that is not committed needs a command that says where it goes (`--out`), and the pack's contributing page says what to do on the owner's keyword. *Seen once:* adcut (`tests/test_overview.py`; its `--out` is not yet on its main branch, 2026-10-28; the playbook's own `tools/overview_page.py` has it).

## Advice is recorded, then read back (from the video-ads skill pack, 2026-10-22)

A pack that writes nothing to a platform still gives advice, and advice with no memory repeats itself and cannot be judged. A request is a record: after the agent asks the producer for N creatives, one verb lands a raw record; the next report counts what was asked and not started as in production, matches a request to the first start after it, and asks again after two lead times with no start. A proposal is a record, once a day: the next report says `open`, then `taken` when the budget moved the proposed way by half the distance, else `not_taken`. The record is raw, written by a verb, never by a report; what is read back is what was done, not what it earned, so every proposal carries `no_counterfactual`; every window is a registered draft the owner confirms. *Seen once:* video-ads (`demand_log.py`, `allocation_log.py`).

## A rate learned from a stream is a flow; a threshold with no right answer is picked by a rule on a replay (from the video-ads skill pack, 2026-10-22)

Two numbers the budget logic rests on looked like constants and were not. The cost of a verdict: the mean spend of finished creatives drops the ones still running and the starved ones (survivorship); the measured quantity is a flow, money spent in the exploration states over eight weeks divided by verdicts reached, shrunk toward the lifecycle's doubt line by n/(n+k) while verdicts are few. On the first client: 540 and 154 per verdict in its two markets, nothing typed. The evidence bar a move must clear has no known right value, and the owner could not judge "1.64": a replay runs at each bar of a fixed grid and takes the lowest at which few moves are undone within a week, else the base value, and the output says `calibrated` or `base`. *Seen once:* video-ads (`docs/creative-demand.md`, `docs/allocation.md`).

## Retiring a subsystem: map it, prove only it went, keep what another pack reads (from the video-ads skill pack, 2026-10-23)

The video-ads pack retired a Meta-era loop its newer layers had replaced, about 10,000 lines in one merge request. The steps that held: ask with evidence, by running every verb of the old loop on a copy of real data and showing which return anything; map before deleting, from the import graph of the verbs that stay (one page helper was still shared and moved out first); let the guards list the rest, in order: the verb table, the CLI forwarding lists, the registries, the message codes nothing emits (deleted by script), the rendered `.gitattributes`, the pinned README text; owner files are not edited, their `.agent.tsv` siblings say *retired*; the golden diff proves only this went, and the merge request quotes the removed cases; keep what another pack reads, and what only the retired code used becomes its own roadmap row. *Seen once:* video-ads (ROADMAP D102, X124).

## The interpreter on the machine is not CI's (from the video-ads skill pack, 2026-10-22)

A pipeline failed with every test green locally: `skill-pack.toml` held an inline table across several lines (TOML 1.1), which the developer's Python 3.15 reads and CI's 3.12 refuses. Run the whole suite on the interpreter CI uses before pushing (`python3.12 tests/run.py`) and say so in the agent instructions; a change that depends on the interpreter, the OS or a schema waits for its own merge request's pipeline before the agent merges. *Seen once:* video-ads (merge request 79; its CLAUDE.md "Tests" invariant).

## Ask another pack for nothing you can do with what it already has (from the video-ads skill pack, 2026-10-22)

Video-ads needed a batch of new creatives to run as one ad group and first asked the producing pack (adcut) for a `move` column, a forced batch code and a warning. The owner's reminder: the producer's job is making videos; if the consumer can do it, the consumer does. Nothing was needed: the producer's `variants spawn` already took a test-group name and `variants handoff` listed what it had not exported; the group comes from the platform's own export, so the contract got no new column. Rules: before asking another pack, list what its CLI and documents already give and what the consumer's agent can do with them, and the ask says what was tried; a unit the platform's export already names is not added to a contract; a limit the producer admits is recorded in `docs/research/` so it is not asked again. *Seen once:* video-ads (R77, R78, D96).

## A rule that overrides another stage's state is tested at the override (from the video-ads skill pack, 2026-10-22)

A new rule picked a creative's wallet from its ad group's state and overwrote the creative's own; its tests covered the group's judging function alone. Every run was green while a brand-new creative in an old, judged group was paid from the performance wallet, so the exploration wallet read zero on the first client and performance creatives went from 24 to 134. Rules: when a rule overrides a value another stage owns, the combination is a pure function with its own cases (`pay(own, group)`), and an override that can only hold money back is easier to believe than one that can grant it; a replay on real data before and after, both numbers quoted, shows an over-reach a unit test cannot; a milestone closes with a review of its whole diff, each finding its own commit under the strict golden diff. *Seen once:* video-ads (D97).

## A fact the client has not given is a typed optional field and a rule that says it does not know (from the video-ads skill pack, 2026-10-21)

Three times the pack was stopped by a number only the client knows (a currency rate, the lowest daily budget, the target return); each time the owner's answer was the same: build the field and let the client fill it. The fact gets a registry row (`ssot/fact_keys.tsv`: type, unit, bounds, optional, a sentence for the person who fills it) and nothing reads a default; the rule that needs it says so in its output when empty (`limits: {min: null}`, a coded warning) and does what it can without it (a request bound by money alone, a sum across two currencies refused until a rate is confirmed); a public lookup may suggest a value, never store it; the roadmap row is a waiting item ("structure built; the client fills"), so the owner's list holds only decisions. *Seen once:* video-ads (W34, W20 to W29, X120).

## Reading a client's software by its screens: the CLI first, the browser for what it lacks, nothing saved (from the video-ads skill pack, 2026-10-14 and 23)

Before a guarded browser module exists ([the 2026-10 design](history/workbook-and-browser-ops-2026-10.md)), the practice on a client's media-library tool: fresh numbers come from the pack's own pull (a saved report's export), and the browser answers only what the export cannot (what the report builder offers). The session is the owner's, already signed in; the agent enters no credential, opens each picker and closes it with "discard changes", downloads nothing, and does not go around a control the session's guard refused. What was seen is written down the same day, dated, in a research file, and the roadmap rows it answers are updated: a screen read that lives only in a chat is looked up again. A search box in such a UI can answer late; wait before concluding something is absent. *Seen twice:* video-ads (`docs/research/time-of-day-and-video-metrics.md`, its client folder's intake note).

## What an agent loads is measured and held by a test (from the adcut skill pack, 2026-10-22 and 27)

An agent pays for every byte it loads. adcut measured it (`tools/context_cost.py`) and held it in a test (`tests/test_context_budget.py`, table in `docs/context-budget.md`): the always-loaded `SKILL.md` stays under 22 KB, a procedure of many steps is an index plus one file per phase an agent reads when it is on that phase (the formula miner went from 26 KB to 7 KB plus four files), each default `--brief` output is far smaller than `--json`, and the roadmap an agent reads is a generated page of a few KB. Two things inflated it again and were cut: a session's state written into a `docs/` page (it belongs in the client workspace, `reports/handoff-<date>.md`, as [session-handoff](../templates/session-handoff.md) says) and a generated page committed to git. *Seen once* (adcut); the size numbers are its own.

## Ecommerce SEO Skill Pack, first non-manufacturer client (2026-10)

The SEO pack, calibrated on B2B manufacturers, closed a full loop for its first software client in one day: a blog page from writing to a merge request into the client's protected site. *Seen once* (2026-10-15). Nine lessons, kept in full there: a check ships with a known-bad input it must refuse; a regression is judged against the baseline on the same copy; a check reads the representation the consumer sees; a rule that depends on the client's kind is a registry column, never a branch; every large read verb has narrowing flags and a `--summary`; a protected main is written through a work branch and a merge request with an amend path; prove the door is open before asking the owner for a code; allocate shared ids where the writes meet; a copied file set carries a stamp naming its source. Full text: the pack's `docs/playbook-lessons-2026-10.md`.

## A host pulls a private skill pack with a read-only deploy key, one per host and repository (from the adcut skill pack, 2026-10-27)

A host that only installs or updates a pack gets a **deploy key** of that one repository: **read-only**, generated **on the host**, one per host and repository (a platform may refuse one key on two repositories). Only the public half leaves the host; the private half never goes into a chat, repository or ticket. A lost host is then one revoked key. A deploy key cannot file issues: a token limited to that repository and to Issues is a separate decision of the owner; otherwise the agent reports in the channel and a person files. Steps: [install checklist](../templates/install-checklist.md#a-private-skill-pack-a-read-only-deploy-key-per-host-and-repository). *Cost:* a repository that moved to a private host left every host unable to update; time a clone from the host before switching, a host abroad may reach the service slowly. No code enforces this. *Seen once* (the adcut skill pack).

## A host that holds the credential: the pack reads the file the host writes (from the Meta skill pack, 2026-10-29)

A client's own agent may reach the platform through a connector it calls in a tool call: named actions, the login kept by the workspace, never handed to code. The pack then holds no credential and has no `pull`; the agent writes the report as a file in the columns of the platform's own export, and `import` reads it unchanged ([the one door](rules.md)). *Paid for:* the connection showed active a day after its login expired, the only sign an error code on read, so the daily file needs a freshness check and the agent a note when a pull fails; an agent asked the data's owner before every share until given one standing approval; and an agent keeps its host's details private, so before it installs a pack the pack needs a sheet of what it calls, reads and writes. *Seen once:* the Meta skill pack.

## The dealers of a competitor are the best downstream customers: a pattern seen once (from the SDR skill pack, 2026-10-30)

A client whose direct competitors sell through dealers can prospect those dealers: they already sell the category to the wanted buyers, so the end customers they reach and the ones the client wants are nearly the same. It holds when the competitors sell through dealers, the client sells to dealers too, a dealer's pages show what it carries, and no exclusive contract closes the dealer to the client's product. What went wrong: a list of dealers names brands the client never confirmed, includes the competitor's own branches and directory sites, and puts a brand's name where the company's name should be. The pattern is kept in the SDR skill pack's `docs/architecture/competitor-channel.md`; it becomes a workflow step here when a second client or pack uses it. *Seen once.*

## When the hosted CI cannot run, a clean clone and two other machines are the check (from the SEO skill pack, 2026-10-31)

A pipeline that fails with zero steps (a billing lock) checks nothing, and waiting for it blocks every merge. Keep rule 4's two checks and move both: the whole local suite on the merge result before merging, then a fresh clone of main run in a temporary folder (it catches a file never committed; 1 min 45 s for 9,283 tests). A change that depends on the OS, the interpreter, a tty or the human gate also goes to two host agents on Linux, each asked once: a commit, the exact commands, three lines back (commit, `RESULT`, Python and `uname`), no secrets. *Paid for:* a host that cannot clone says so, and two others are enough; hosts clone through their own deploy-key alias, so write "your clone address", never the URL. *Seen once:* the SEO pack, from 2026-10-30. Its rule: CLAUDE.md, "hosting".
